# 在途 Onway · 实现对齐说明

版本：0.5.4

## 需求来源与优先级

本项目不再把旧版“纵向多卡片列表”作为产品基准。发生冲突时，按以下顺序处理：

1. 用户在当前任务中的明确要求；
2. `docs/在途_Onway_产品需求文档_V0.1.0.md`；
3. `prototypes/01-欢迎.html` 至 `17-历史.html`；
4. 本文件；
5. 现有实现。

颜色和图标分别参考 `在途颜色原型设计.html` 与 `在途图标原型设计.png`。

## 产品定义

在途是一个只展示“当前最该看的一张卡”的通勤助手。它围绕用户保存的起点、目的地和通勤方案，连续呈现准备出发、步行、候车、乘车、换乘、最后一段步行与到达结算。

产品必须少打扰、可纠正、诚实展示数据来源。没有可靠数据时应降级或冻结，不得伪装实时公交、后台通知或已经取得的系统权限。

## 页面与状态

实现需覆盖以下 17 个原型页面：

1. 欢迎；
2. 标记家和目的地；
3. 选择常用方案；
4. 权限说明；
5. 准备出发；
6. 步行至上车站；
7. 候车；
8. 乘车中；
9. 换乘；
10. 最后一段步行；
11. 到达结算；
12. 空闲；
13. 定位丢失；
14. 临时行程取消；
15. 更优方案；
16. 设置；
17. 通勤历史。

主流程页面保持单主卡片。设置与历史是独立页面，不和主流程并排堆叠。

## 不可破坏的产品规则

- 起点和终点的可信边界为 50 米。
- 单次 GPS 跳点不能触发行程开始、取消或完成；至少需要连续观测确认。
- 离开起点后先创建临时行程；返回起点则取消，并且不写入历史。
- 进入目的地可信边界后才完成有效通勤。
- 用户手动纠正的阶段优先于自动推断。
- GPS 不可用时冻结阶段和站点进度，不允许仅按时钟自动跳站。
- 选定方案后，上车站、方向、下车站应提前可见。
- 多段路线必须展示换乘状态。
- 更优方案只能在出发前建议，由用户采用或忽略，不得静默切换。
- 历史基准应在加入本次记录之前计算，并按方向、方案分别统计。
- 原型演示到达不得写入真实历史。

## 数据诚实性

| 数据 | 当前实现 | 展示要求 |
|---|---|---|
| 当前定位 | `sys.gps` | 仅有可信定位时用于实际边界判断 |
| 家与目的地 | 原型示例或用户现场标记 | 必须区分示例地点与真实标记 |
| 路线、班次、站点进度 | 原型示例 | 明确写出“估算”“示例”或“非实时” |
| 原型历史 | 示例统计 | 与真实历史条数分开显示 |
| 后台定位与异常通知 | 桌面环境不可验证 | 只做权限说明，标注待移动端真机验证 |

禁止声称当前构建已经接入实时公交、后台持续运行、系统通知或外部地图实时路线服务。

## 视觉约束

- 页面底色：`#F5F5F7`；
- 白卡：`#FFFFFF`；深色主卡：`#272729`；
- 主文字：`#1D1D1F`；次文字：`#7A7A7A` / `#666666`；
- 交互蓝：`#0066CC`；深色卡亮蓝：`#2997FF`；
- 警告橙：`#FF9F0A`；
- 主卡圆角：28；
- 语言简短、克制，避免多余装饰和 emoji；
- 一屏只强调一个主行动。

## 当前实现入口

- 主实现：`bundle/main.splash`
- 权限与版本：`bundle/manifest.json`
- 商店文案：`bundle/listing.json`
- 真实运行截图：`bundle/screenshots/`

`_gen_splash.py` 是旧版生成器，只保留历史参考并已停用，不能再用它覆盖主实现。

## 验收

每次修改至少完成：

1. 用全新应用数据跑通首次设置至准备出发；
2. 跑通步行、候车、乘车、换乘、到达和历史；
3. 验证定位丢失、临时取消、更优方案三个分支；
4. 检查所有可见按钮没有被裁切；
5. 检查运行日志无错误；
6. 使用 `tools/octo check` 校验应用包；
7. 商店截图必须来自实际运行界面，禁止使用设计稿代替。
