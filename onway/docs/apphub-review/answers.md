# 作者自检回答 · onway 1.0.2

日期：2026-10-06。以下是作者基于源码和本机运行的回答，不是独立审计或官方准入结论。建议路由：human-review，先确认宿主接入路径，暂缓将本包作为标准宿主完整可用应用入库。

## 1. 功能声明是否与源码一致？

`bundle/main.splash` 的 `send()` 把操作写入私有 commands 目录；`poll()` 读取配套后台生成的 `view-state.json`。页面包含首页、路线比较、常用地点、历史、偏好及服务状态。后台未接入时，首次启动 12 秒后显示“此宿主尚未接入在途后台”。listing 明确说明完整功能依赖配套后台与定制宿主，普通商店安装未完整验证。

完整实现证据位于包外：`backend/v060/engine.py`、`worker.py`、`services.py`、`bus.py`、`card-v060.splash` 和 `runtime/`。Windows v1.0.1 演示包使用上述后台和定制宿主，本机隔离环境已验证启动、地图与 AI 连接；不将这些证据等同于当前普通 store 安装成功。完整户外行程未验证。

## 2. 平台和分类是否合适？

分类 travel；只声明本机实际验证过的 Windows。没有声明手机端、锁屏、宿主退出后仍运行或休眠后持续定位。listing 明确指出当前依赖，不承诺其他电脑或普通宿主完整兼容。

## 3. 权限和 hosts 是否匹配？

storage：保存私有命令、读取后台状态。location：定制宿主向配套后台传入系统定位，失败时保留状态并允许手动起点。glance：原方案为行程卡申请，但当前自定义窗口由包外宿主管理，主脚本没有直接调用标准 `glance.publish`；需在最终标准宿主接入时重新核对、删除不需要的授权。

脚本只读取 `{{assets}}` 本包字体、图标等宿主资源；没有脚本对外网络请求，所以没有 net 或外部 network.hosts。**不能由此推断完整产品不联网**。包外配套后台请求 `120.53.104.174` 网关代理地图、天气、MiniMax；公交请求 `ts-api.tundrey.com`。服务代码另保留自行部署/配置路径，例如高德官方服务及指定地图代理，详见 `services.py`、`gateway_client.py`。这些包外请求不受此脚本 manifest 的 hosts 隔离名单覆盖，是当前接入阻碍之一，需要宿主集成审核。

本次未通过添加未知服务名、宽泛权限或执行二进制绕过沙箱。bundle 没有 Python、宿主可执行文件或共享令牌。

## 4. 是否有欺骗性系统、付款或登录界面？

UI 使用在途品牌，不伪装系统登录、支付或第三方产品。脚本没有密码/PIN/一次性码输入。包外后台另提供回环地址上的开发者配置页，可接收自行配置的 API Key 并通过 DPAPI 保存；**它不是官方 host-owned sheet**，不声称符合标准商店服务授权路径。演示包不需要用户填写网关凭证。

当前 bundle 的可见内容用于用户导航、输入、状态和依赖说明，没有给审核助手下达命令。AI 提示词位于包外 Python 服务，作为模型任务上下文；需审核完整源码，不能仅依据 bundle 的扫描结果判断完整产品。
